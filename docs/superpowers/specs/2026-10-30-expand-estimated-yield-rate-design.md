# 扩大成品利用率字段范围设计

## 意图

允许 ERP 中有效的成品利用率（例如 `1500.9` 和 `5894.55`）写入 QMS 标准字段，不再因为 `estimated_yield_rate DECIMAL(5,2)` 的 `999.99` 上限而被同步工具置空。

## 方案

- 新增 Flyway V44 迁移，将 `qms_work_order.estimated_yield_rate` 扩为可空的 `DECIMAL(10,2)`。
- ERP 同步工具采用同一范围，上限调整为 `99999999.99`；超过范围的极端值仍保留在 ERP 原始英文字段，并将 QMS 标准字段留空。
- Java API 继续使用 `BigDecimal`，前端继续使用数值展示，不改变接口结构。

## 部署约束

先部署并成功执行 QMS V44，再发布新版 ERP 同步工具。若顺序相反，新工具可能把超过 `999.99` 的值发送给旧数据库，导致写入失败。

## 非目标

- 不调整自动监控的 5 分钟检查间隔。
- 不修改历史迁移 V22。
- 不自动修正或换算 ERP 源值；扩大范围不代表所有大数值都一定是业务正确值。

## 验证

同步工具回归测试覆盖 `1500.9`、`5894.55`、新上限以及超过新上限的值；QMS 后端执行测试和打包，Flyway 迁移随产物发布。

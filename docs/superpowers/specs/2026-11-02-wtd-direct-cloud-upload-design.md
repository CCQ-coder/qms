# 旺通达飞针机直传线上 QMS 设计

## 目标

每台旺通达 XP 设备继续扫描 `D:\WTD\JOBS\<任务>\<任务>.ini`，但通过 HTTPS 将原始字节和本机状态直接送到线上 QMS。线上 QMS 保存原始文件、解析 `Test_Counters`，复用现有遥测入库、工单匹配和 FQC 投影。切换完成后，SCBGX 不再负责这批设备的文件中转、解析和状态转发。

## 方案

- **选用：设备直传线上 QMS。** 符合设备不再依赖 SCBGX 的要求，代价是需为 XP 安装包验证 TLS，并在线上建立设备专用入口和持久存储。
- 备选：SCBGX 只转发原文件，由线上解析。设备端改动较小，但仍依赖局域网和 SCBGX，不符合已确认的目标。

## 设备端

- 基于已部署的 `hr_sync` `codex/flying-probe-host-status` 分支，保留无窗口 EXE、文件每 5 分钟/状态每 1 分钟的计划任务、设备编号和本机采集逻辑。
- 新直传配置使用 HTTPS 服务地址、`device_id`、该设备专用上传凭据和可信 CA 证书；不在设备保存 QMS 全局网关令牌。服务地址不得是公网明文 HTTP。旧 `target_root` UNC 配置继续可用，供分批切换和回滚。
- 文件请求携带设备编号、任务名、原始 INI 字节、SHA-256，以及**旧共享复制算法将写入目标 TXT 的**创建与修改 FILETIME（100 纳秒整数）。旧算法先将源文件的 `st_ctime`/`st_mtime` 秒值乘以 10,000,000、四舍五入，再加 Windows 纪元偏移；直接读取源文件原始 FILETIME 可能改变旧记录编号。中文编号和任务名写入 UTF-8 JSON，不放进 HTTP 头。
- 只有收到服务端成功确认才更新云端专用的 `cloud_sync_state.json`。保留旧 `sync_state.json` 结构和原 UNC 配置备份，使原先只传到共享目录的文件首次直传时补传，并可直接恢复旧 EXE、配置与任务；超时和服务端失败保留下次重试。
- 电脑状态使用独立的每分钟任务，沿用现有 JSON 字段，直接发送到线上 QMS；失败不伪造成功。

## 线上 QMS

- 新增文件和电脑状态两个设备专用 POST 接口。给现有设备网关映射增加唯一的上传令牌哈希；每台设备持有不同的随机令牌，过滤器按哈希定位唯一映射、验证租户和设备，再设置租户上下文。请求中的设备编号必须与令牌绑定的 `machineName` 一致；映射删除或令牌撤销后拒收。
- 用数据库迁移给映射表增加可空且唯一的 `upload_token_hash`（32 字节随机令牌的 SHA-256）。仅管理员可通过 API 一次性签发/轮换和撤销；明文令牌只在签发响应中出现一次，由安装人员写入该设备配置，数据库、普通列表接口和日志均不显示明文；首版不新增管理页面。
- 将完整 JSON 请求限制为 11,500,000 字节、解码后原始 INI 限制为 8 MiB，校验 Base64、SHA-256、任务名及设备映射。原始文件按内容哈希原子保存到 `QMS_ATTACHMENT_LOCAL_ROOT` 下的独立目录，线上部署必须挂载持久卷。
- 解析规则、`sourceFile=<设备编号>/<任务名>.txt`、`startTime`、`deviceTime` 和 `FPT-...` 记录编号须与现有 SCBGX `ProbeRecords` 一致。服务器使用上述复制后 FILETIME 按 SCBGX 原时区还原时间，并用 C#→Java 黄金样本比对记录编号，避免历史补传产生新批次。只接受唯一且有效的 `Test_Counters` 行。
- 文件落盘并经现有 `EquipmentTelemetryApplicationService` 接收后才返回成功；重复请求由稳定记录编号和服务端唯一键去重。状态入口核对 JSON `deviceId` 与令牌映射，并用映射的 `machineName` 生成现有 `GatewayHostStatusRequest.hostName`；晚到的旧样本不得覆盖较新的状态。生产与开发安全配置均不得绕过设备令牌校验。现有网关接口保持可用。

## 部署与切换

- 公网 `106.227.69.144:5173` 同时承载原 HTTP 页面和经 TLS 识别的设备 HTTPS 入口；设备配置为 `https://106.227.69.144:5173`，使用包内可信证书和线上持久上传目录。仍需在实际 XP 32 位包上验证 TLS 握手与时钟。XP 包需在具有 `.tools\python34-x86` 与 PyInstaller 3.4 的 Windows 构建机上生成，开发机测试不能代替现场握手。
- 先部署线上接收与解析，选一台设备验证原始文件、状态、遥测及 FQC；再逐台切换设备配置。核对成功后停用 SCBGX 对应采集/转发任务，且仅让线上 QMS 实例执行飞针投影调度。
- 切换失败时恢复设备原 UNC 配置与 SCBGX 任务；不删除设备源 INI、旧共享文件或线上原始文件。

## 边界

不修改旺通达生成 INI 的软件，不改变 QMS 现有工单/FQC 算法，不把全局网关令牌分发到 XP。线上 SSH 登录信息及 HTTPS 证书部署方式由现场环境确定；代码中的服务地址保持可配置。
